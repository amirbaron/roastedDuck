# S3 exact-object read checkpoint

2026-10-31. Historical read checkpoint645; see [the newer listing checkpoint](httpfs-s3-listing-parity.md). The release goal remains incomplete.

The pinned HTTPFS loader now registers S3 positional reads beside HTTP(S), plus
the `s3`, `aws`, `r2` and `gcs` config-secret types. Supported exact-object paths
include `s3://`, `s3a://`, `s3n://`, `r2://`, `gcs://` and `gs://`. Each HEAD/range
request receives a fresh AWS SigV4 signature, using ring's SHA-256/HMAC primitives.
GCS bearer authentication and unsigned public reads use their respective paths.
No object-body, table or query cache was added. Existing ETag validation remains
in use, and the accepted memory budgets and `release_on_unpin` policy are unchanged.

Secret selection follows pinned C++ HTTPFS commit
`4bc690dba4496c765777a0269d48fdbaff7cdc11`: first matching secret type in
`s3`, `r2`, `gcs`, `aws` order, with the core manager's scope selection within
each type. HTTP-secret fallback applies only when no S3-type secret matched and
`merge_http_secret_into_s3_request` permits it. Extra headers and proxy/TLS values
reach the request; an HTTP bearer token does not replace S3 SigV4 authorization.
Environment credentials are captured as global values at LOAD, preserving option
defaults and AWS_REGION precedence over AWS_DEFAULT_REGION. Disabling global S3
configuration still permits session values and scoped secrets.

Generic HTTP redirects are disabled for signed S3 requests. Region redirects must
be implemented by selecting the new endpoint and signing a new request; that
lifecycle remains open. Session tokens are never forwarded by generic redirect
handling. Credential-bearing transport/resolver Debug output omits secret values.

## Open gates

S3 listing/globs, multipart writes/deletion, region redirects, credential refresh,
version pinning, additional URL/protocol/error cases and broader service controls
remain open. Unsupported writes/listing/refresh return explicit errors. Full
HuggingFace support, remaining HTTPFS settings, system trust-root behavior and
autoload/startup integration are also unfinished. Persistent secret-file and
transaction behavior still have the gaps documented in `secrets.rs`.

No full selected-client matrix, Linux/iOS runtime refresh, final SQL/shell/ADBC,
cross-engine storage/WAL or coupled speed/RSS acceptance follows from this
checkpoint. The earlier targeted Python/Go/Swift HTTP checks used older images.
Required clients remain Python, Go and Swift; required platforms remain Mac ARM64,
iOS ARM64 device/simulator and Linux ARM64/x86_64. Final common-source signed
release verification and documented performance acceptance are still required.
